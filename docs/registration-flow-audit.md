# 가입·약관 열람 흐름 점검

점검일: 2026-09-10

## 범위와 결과

로그인 진입, OAuth 콜백, 가입 필수 확인, 이용약관·개인정보처리방침 열람과
복귀, 가입 저장, 만 14세 미만의 중단, 오류 복구를 점검했다.

| 확인 항목 | 결과 |

| 서버 가입 확인 성공 | 인증된 계정에 대해 세 가지 필수 확인을 전달하고 active 응답 |

## 수정 사항

- `registration_consent_dialog.tsx`: 계정별 컴포넌트 상태, 조회 대기·실패·제한 안내,
  기본 모달 dialog, 저장 중 입력 차단, 다른 계정의 늦은 저장 응답 무시,
  미성년자 중단 문구와 재선택 동작.
- `user_queries.ts`, `auth_button.tsx`, `account_page.tsx`: 회원정보 query key를
  인증 계정별로 분리.
- `auth_session_cleanup.tsx`: 계정 변경 직후 캐시를 동기적으로 비워 새 계정의
  요청을 뒤늦게 지우는 경쟁 조건 제거. QueryClient.clear 자체가 기존 요청을 취소한다.
- `app/auth/callback/route.ts`: 회원정보 조회 10초 제한과 신규 회원 오류 구분.
- `login_page.tsx`, `social_auth_setup.md`: 실제 가입 시점과 현재 카카오 로그인 흐름에 맞게 설명 수정.
- Backend `test/registration.e2e-spec.ts`: 인증, 필수 확인, 잘못된 요청, 성공·실패 HTTP 회귀 테스트 10개 추가.

공개 Backend API, 동의 버전, DB schema와 migration은 변경하지 않았다.

## 검증 방법과 한계

실제 localhost:3000 Next 앱에서 두 전문과 복귀 링크, 로그인 오류 표시,
외부 복귀 주소 차단을 확인했다. 가입 UI는 실제 컴포넌트와 빌드 CSS를 가져온
별도 로컬 fixture에서 인증·API·라우터를 대체하여 확인했다.
실제 사용자의 카카오 로그인, 가입 동의 저장 또는 계정 탈퇴는 수행하지 않았다.
따라서 실제 카카오 서비스부터 운영 DB까지 연결하는 통합 검증은 별도로 필요하다.

OAuth 콜백은 실제 소스를 임시 Node 테스트에서 외부 의존성만 대체하여 7가지
상황을 검증했고, 내부 복귀 경로 검사도 6가지 입력으로 확인했다.
임시 fixture와 콜백 실행 파일은 저장소 밖 `/tmp/saju-registration-flow-check`에 두었다.

검증 결과:

- Frontend `pnpm lint`: 통과.
- Frontend `pnpm build --webpack`: 통과. 로컬 환경의 Turbopack 프로세스·포트 제한을 피한 빌드이며 설정 변경은 없음.
- Backend `npm run lint`: 통과.
- Backend `npm test`: 79개 통과.
- Backend `npm run test:e2e`: 53개 통과, 이 중 신규 가입 테스트 10개.
- Backend `npm run build`: 통과.
- 두 저장소 `git diff --check`: 통과.

## 운영 적용 전 남은 사항

두 전문은 여전히 시행 전 초안이다. 시행일, 연락처, 개인정보 보호책임자,
실제 처리업체·이전 국가·보유기간 등의 미확정 내용을 채운 후 서버 동의 버전과
게시본을 맞춰야 한다. 현재 서버의 `v1`은 확정 게시본을 식별하는 절차가 연결되어
있지 않으며, 이번 점검에서 운영 동의 버전이나 가입 정책을 임의로 바꾸지 않았다.
만 14세 이상 선택은 실제 이용자의 자기 확인이며 본인확인 자료를 통한 연령 검증은 아니다.
