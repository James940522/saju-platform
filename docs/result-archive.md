# 결과 보관함

- `/results`를 하단 마지막 메뉴인 **결과 보관함**으로 제공한다. 내 만세력은 보관함 상단 링크로 접근한다.
- 상품 필터는 가로 스크롤, 결과 목록은 document 세로 스크롤을 사용한다. 필터는 상단에 유지하고 하단 메뉴와 safe area의 여백은 기존 TabShell이 처리한다.
- 현재 카탈로그에 공개된 상품을 필터로 표시한다. 과거 결과가 있는 숨김 상품도 분류에서 접근할 수 있다.
- 실제 재물운 랭킹은 기존 `GET /v1/reading-jobs`의 계정별 저장 내역을 사용한다. 별도 저장 요청 없이 요청 시점부터 보관함에서 확인하고 완료 시 같은 링크로 결과를 연다.
- 진행 중인 작업이 있을 때만 3초 간격으로 갱신한다. 실패 내역도 다시 확인할 수 있다. 기존 풀이 목록과 query key 및 pagination 설정을 공유한다.
- 최신 요청 순서로 표시하고 cursor로 이전 내역을 더 불러온다. 페이지가 남아 있으면 개수에 `+`를 표시한다. 현재 불러온 페이지에 상품이 없더라도 이전 결과를 더 볼 수 있다.
- 전생 관계는 기존 정적 예시 화면이다. 예시 결과의 보관 여부와 시각만 계정별 sessionStorage에 기록한다. 새로고침 후 복원되며 해당 탭을 닫으면 사라진다. 브라우저 보관을 실제 서버 저장이나 결제로 표현하지 않는다.
- 기존 예시 결과의 로그인·프로필·예시 결제 확인은 유지한다. 실제 결과에는 서버 삭제 API가 없으므로 임의의 삭제 버튼을 제공하지 않는다. 예시 결과만 보관 해제할 수 있다.
- 다른 상품은 결과 생성 API가 연결될 때 실제 저장 결과를 추가한다. UI 확인용 가짜 결과를 계정 내역에 자동으로 넣지 않는다.

## 검증

`pnpm test:result-archive`는 페이지 중복 제거, 상품 분류, 한국 날짜 경계, 계정별 예시 보관 복원/해제, 브라우저 저장 실패, 로그인·로딩·오류·빈 목록·진행 상태를 검증한다.

임시 예시 화면에 18개 카드를 넣어 320px/390px 브라우저에서 필터 가로 스크롤, 상품별 목록 변경, 전체 세로 스크롤과 마지막 카드의 하단 메뉴 여백을 확인했다. 검증 후 임시 route는 제거했다.

Backend 계약 및 DB schema 변경은 없다. API 인증·소유권과 기존 결과 URL은 유지한다.
